행사 장비 대여 서비스 — 첫 Vercel 배포에서 함정 3개를 다 밟았다

야외 행사용 장비를 빌려주는 서비스. 고객 페이지(목록·상세·견적·마이페이지·갤러리)와 관리자 페이지(대시보드·견적·장비·회원)를 만들고 배포까지 마쳤습니다.

Next.js 14 + Prisma + Supabase + NextAuth v5 + Cloudinary → Vercel

첫 서버리스 배포에서 밟은 것 3개

1. Prisma Client가 빌드 환경에 없다

로컬에선 되는데 Vercel 빌드가 실패합니다. 빌드 스크립트에서 클라이언트를 생성해줘야 합니다.

2. 빌드 타임에 DB를 부른다

서버 컴포넌트가 DB를 직접 읽으면, 빌드 시점에 프리렌더하면서 DB에 붙으려다 터집니다. 빌드 환경엔 DB가 없죠.

해당 페이지에 이 한 줄. 부수 효과로 항상 최신 데이터가 나옵니다.

3. 커넥션 풀이 터진다 — 이게 제일 아팠습니다

배포 후 트래픽이 조금만 늘면 max clients reached. 원인은 서버리스 함수 인스턴스마다 DB 커넥션을 따로 잡기 때문입니다.

세션 모드 풀러(5432)를 쓰고 있었는데, 서버리스에선 트랜잭션 모드(6543) 를 써야 합니다.

?pgbouncer=true&connection_limit=1
  • pgbouncer=true — prepared statement를 끕니다(풀러가 지원 안 함)
  • connection_limit=1 — 함수당 커넥션 1개

서버리스는 “서버가 없는” 게 아니라 서버가 수십 개 생겼다 사라지는 것입니다. 커넥션처럼 공유 자원을 쓰는 부분은 전제를 다시 세워야 합니다.

그리고 사업 쪽 결정 하나

가격을 공개 API 응답에 담고 있었는데, 리뷰에서 지적받아 뺐습니다. 화면에서 안 보여도 API 응답에 들어 있으면 공개된 것입니다. 단가를 가리기로 했으면 데이터 레벨에서 막아야 합니다.

멈춘 지점

카카오·구글 OAuth 키 발급과 실제 장비 사진 업로드가 남았습니다. 기능은 다 돌아가는데 내 손을 떠난 일(키 발급·사진 준비)에서 멈춰 있습니다.
