쿠팡 파트너스 자동 포스팅 사이트를 하루 만에 만든 과정 (그리고 "개꿀"이 아니었던 이유)

“쿠팡 베스트 랭킹을 요일별로 크롤링해서 자동 포스팅하면 개꿀 아닌가?” — 이 한 줄에서 시작해서 하루 만에 사이트가 라이브됐고, 그 과정에서 처음 생각이 어디가 틀렸는지도 같이 배웠습니다. 결과물은 오늘딜입니다.

크롤링은 하면 안 되고, 할 필요도 없었다

첫 가정부터 틀렸습니다. 쿠팡 사이트 크롤링은 약관 위반이고 봇 차단이 강합니다. 대신 쿠팡 파트너스 공식 Open API가 있습니다 — 골드박스, 카테고리별 베스트, 검색, 딥링크, 그리고 클릭·주문·수수료 리포트까지. HMAC 서명만 맞추면 됩니다.

실측으로 알게 된 것 하나: API가 주는 상품 필드는 이름·현재가·이미지·수익링크·로켓배송·순위뿐입니다. 정가·할인율·평점·리뷰는 없습니다. 처음 그린 화면에 “▼41% 할인, 별점 4.8, 리뷰 요약”을 넣었다가 전부 지웠습니다. 실측 전엔 모른다는 걸 또 확인했습니다.

그래서 차별점은 “우리가 매일 저장한 가격”

API가 안 주는 걸 우리가 만듭니다. 매일 아침 9시에 골드박스와 7개 카테고리 베스트를 수집하고 가격·순위를 120일 저장합니다. 그 이력으로:

  • “우리가 본 N일(관측 M회) 중 최저가” — 쿠팡 최저가 보장이 아니라 우리가 본 기간 안에서, 같은 판매자·옵션끼리 비교
  • “어제보다 ▼12%”, “순위 ▲5”, “5일째 TOP 10”, “신규 진입”
  • 30일 가격 그래프

이건 쿠팡 자체 페이지에도 없는 정보입니다. 자동 생성 글이 검색엔진에서 살아남으려면 남한테 없는 데이터여야 한다는 게 이 사이트의 전제입니다.

파이프라인

GitHub Actions (매일 09:17 KST)
  → 파트너스 API 8회 (골드박스 1 + 카테고리 7)
  → data/snapshots/YYYY-MM-DD.json + prices.json + ranks.json 커밋
  → Python + Jinja2로 정적 HTML 생성
  → GitHub Pages 배포

서버 없음, 비용 0원, PC가 꺼져 있어도 돕니다. 하루 API 호출은 8회로 고정했습니다.

반나절 동안 밟은 것들

  • gh repo create --push가 워크플로 파일 때문에 거부 → 일반 git push로 통과
  • GitHub Pages API의 build_type 값은 workflows가 아니라 workflow
  • 00:00 UTC 정각 크론은 GitHub에서 가장 밀리는 슬롯 — 48분이 지나도 안 돌았습니다. 09:17로 옮기고, 코드 push도 배포를 트리거하게 했습니다(봇의 데이터 커밋은 제외해서 무한 루프 방지)
  • actions/upload-pages-artifact@v7이라고 적었는데 그 액션은 v5까지밖에 없었습니다(v7은 다른 액션). 배포 한 번 실패
  • Jinja에서 dict 키 items는 dict.items 메서드로 잡힙니다

”개꿀”이 아닌 이유 — 숫자로

수수료 약 3%, 쿠키 24시간, 마지막 클릭 귀속. 보수적으로 잡으면:

월 클릭 1,000 × 구매전환 3% × 주문액 5만원 × 수수료 3% × 취소 후 잔존 90% ≈ 월 4만 원
월 30만 원이려면 약 7,400클릭

그리고 자동 생성 랭킹 글은 구글이 명시적으로 걸러내는 부류라 검색 유입은 기대하지 않습니다. 유입은 텔레그램 푸시·사람이 쓴 글·꾸준함에서 나온다고 보고 있고, 3개월 뒤 클릭·주문·수수료 숫자로 계속할지 결정합니다. 중단 기준도 미리 적어뒀습니다 — 2개월째 30일 클릭 300 미만이면 확장 중단, 3개월째 수수료 5만 원 미만이면 종료.

이게 하루 만에 라이브된 이유는 코드가 쉬워서가 아니라, 코드는 AI 에이전트가 거의 다 썼고 제 시간은 결정에만 쓰였기 때문입니다. 그 얘기는 다음 글에서.

이 사이트의 쇼핑정보 섹션은 쿠팡 파트너스 활동의 일환으로, 이에 따른 일정액의 수수료를 제공받습니다.
