discord-bridge — 자동화 결과를 디스코드로 흘려보내기

2026년 6월 08일3 min read

  • 프로젝트
  • discord
  • 자동화
  • 알림
  • mcp

돌아가는 자동화들이 어떻게 됐는지 디스코드로 알려주는 다리. 지금도 AI 레이더 발행과 점검 실패 알림이 이걸 씁니다.

왜 필요했나

자동화를 여러 개 굴리다 보면 “돌았는지” 확인하러 매번 로그를 열어보게 됩니다. 그러다 안 열어보게 되고, 안 열어보면 죽어도 모릅니다.

알림은 그 반대입니다. 내가 안 찾아가도 온다는 게 전부입니다.

만든 것

  • 명령 핸들러, 병렬 호출, 서버 관리 기능
  • 세션 시작 시 봇 자동 구동(훅)
  • AI 레이더 자동 포스팅
  • FastMCP로 볼트 연결

성능 개선에서 배운 것

처음엔 외부 CLI를 subprocess로 띄워 호출했습니다. 느렸습니다. SDK 직접 호출 + 스트리밍 응답 + 컨텍스트 캐싱으로 바꾸니 체감이 달라졌습니다.

이미 있는 CLI를 감싸는 건 빠르게 만들 땐 좋지만, 프로세스를 매번 띄우는 비용은 생각보다 큽니다. 자주 부르는 경로라면 SDK로 내려가는 게 맞습니다.

운영하면서 정한 규칙

알림 채널에 배관 테스트를 쏘지 않습니다. 목적이 있는 채널에 “테스트” 메시지가 섞이면 그 채널을 아무도 안 보게 됩니다. 테스트는 테스트 채널로 보냅니다.

그리고 성공은 알리지 않습니다. 잘 된 걸 매번 알리면 알림이 배경 소음이 되고, 진짜 실패가 묻힙니다. 무소식이 희소식.

멈춘 지점

볼트 검색 명령을 붙이는 단계(Phase 3)에서 멈춰 있습니다. 알림 기능만으로도 충분히 쓰이고 있어서 우선순위가 밀렸습니다.
