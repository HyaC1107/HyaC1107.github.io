AI 레이더 2026-07-24

AI 레이더 2026-07-24

2026년 7월 24일7 min read

  • ai-radar

매일 아침 자동 생성되는 AI 소식 다이제스트입니다. 젬또리(Gemini)가 웹을 검색해 정리하고 검수봇이 사실 확인을 거칩니다. [미검증] 표시가 있거나 출처가 홈페이지뿐인 항목은 원문을 확인하세요.

🤖 자동 생성 (Windows 작업 스케줄러 ttori-ai-radar, 매일 08:00 · 젬또리 agy Gemini 3.5 Flash (Medium)). 클또리 검수를 거치지 않은 원문이다. [미검증] 태그가 붙었거나 출처가 도메인 홈페이지뿐인 항목은 채택 전 반드시 원문 확인할 것. flash가 학습데이터를 최신 정보로 착각해 내놓는 경우가 있다.

🤖 모델/LLM 소식

  • Kimi K3 [미검증] — 2.8조 매개변수 규모의 대형 오픈 웨이츠(open-weights) 모델로, 2026년 7월 27일 전체 가중치 공개가 예정되어 있습니다.
  • Qwen 3.6 27B / 35B-A3B [미검증] — 뛰어난 성능 대 효율성을 입증하며 오픈소스 모델과 상용 모델 간의 간극을 2~3개월 수준으로 좁힌 중형 고효율 모델군입니다.
  • Xiaomi MiMo-V2-Pro [미검증] — MoE sparse 아키텍처를 채택하여 성능 대비 비용을 낮춘 1조 매개변수 규모의 파운데이션 모델입니다.
  • MiniMax M2.7 [미검증] — 자율 디버깅 및 연구 에이전트 작업 등 복잡한 워크플로우에 특화 설계된 에이전트용 모델입니다.

🛠️ 개발 툴·스킬

  • Zerobox — Docker나 VM 없이 OS 네이티브 격리로 AI가 생성한 코드를 안전하게 실행할 수 있는 경량 샌드박싱 도구입니다. (https://github.com/afshinm/zerobox)
  • WebMCP — 웹사이트가 자체적으로 AI 에이전트에 구조화된 도구를 제공할 수 있도록 지원하는 웹 표준 제안 및 구현체입니다. (https://github.com/webmachinelearning/webmcp)
  • google/agents-cli [미검증] — 구글이 공개한 AI 에이전트 제작, 평가 및 배포를 지원하는 CLI 도구입니다.

📄 논문·트렌드

  • Paper2Agent — 정적 연구 논문 및 관련 소스 코드를 대화형 AI 에이전트로 자동 변환해 주는 프레임워크 연구입니다. (https://github.com/jmiao24/Paper2Agent)
  • Loop the Loopies! (arXiv:2607.16051) — 동일 연산 비용에서 기존 Transformer보다 우수한 추론 성능을 보이는 MoE 기반의 순환 Transformer 아키텍처를 제안합니다. (https://arxiv.org/abs/2607.16051)
  • They’ll Verify: How Authority Framing and Laundered Code Turn a Trusted Agentic CI/CD Pipeline Into an Attack Surface (arXiv:2607.19267) — CI/CD 파이프라인에서 권한 프레이밍 기법으로 보안 스캐너를 우회하여 에이전트를 공격하는 위협 분석 연구입니다. (https://arxiv.org/abs/2607.19267)
  • Tool-Making and Self-Evolving LLM Agents in Low-Latency Systems (arXiv:2607.08010) — 에이전트가 스스로 필요한 도구를 생성하고 최적화하여 대기 시간과 오류율을 낮추는 구조를 다룬 연구입니다. (https://arxiv.org/abs/2607.08010)

💡 또리팀 적용 포인트

  • Zerobox를 활용한 CLI 에이전트 코드 실행 샌드박싱: CLI 오케스트레이터는 사용자 시스템에서 직접 쉘 명령어나 파이썬 코드를 실행할 수 있어 보안 리스크가 매우 큽니다. Zerobox를 도입해 deny-by-default 정책으로 민감한 경로(예: ~/.ssh, ~/.aws) 및 의도치 않은 네트워크 접근을 제한하면, 오버헤드가 단 10ms 수준이므로 속도 저하 없이 오케스트레이터의 안정성과 보안을 확보할 수 있습니다.
  • google/agents-cli의 LLM-as-judge 평가 방식 벤치마킹: CLI 에이전트 오케스트레이터의 출력 정확도나 행동 패턴을 지속적으로 개선하기 위해서는 자동화된 검증이 필수적입니다. agents-cli에 사용된 에이전트 실행 결과 평가 절차와 LLM-as-judge 채점 방식을 참고하여, 에이전트 업데이트 시 변경 사항이 안전한지 자동으로 검증하는 회귀 테스트 파이프라인을 구축할 수 있습니다.
  • Tool-Making and Self-Evolving (arXiv:2607.08010) 기반의 동적 도구 생성 체계: 오케스트레이터가 지원해야 하는 CLI 도구와 라이브러리가 너무 많아지면 컨텍스트 토큰 낭비와 정확도 저하(분석 마비)가 발생합니다. 논문의 접근법을 활용해, 에이전트가 복잡한 작업을 만났을 때 기본 제공 도구들의 뼈대를 조합하여 필요한 새로운 임시 헬퍼 도구(스크립트 등)를 스스로 합성·저장해 호출하도록 유도하면 컨텍스트를 절약하고 처리 성능을 극대화할 수 있습니다.
