🤖 모델/LLM 소식

  • NVIDIA Nemotron 3.5 Super VL (120B-A12B) — Mamba-2와 트랜스포머 레이어를 교차 배치한 하이브리드 MoE 구조로 토큰당 12B를 활성화(총 120B)하며, C-RADIO 비전 인코더 및 네이티브 MTP(Multi-Token Prediction) 투기적 디코딩을 지원해 1M 롱컨텍스트 환경에서 고효율 멀티모달 추론과 장기 에이전트 작업을 수행 (https://blogs.nvidia.com/blog/2026/10/15/nemotron-3-5-super-vl/)
  • NVIDIA Nemotron 3.5 Bolt E4B — Gemma 4 E4B 베이스를 강화학습(RL) 사후 훈련하여 Q4 양자화 기준 약 4GB VRAM 환경에서도 로컬 대화 및 멀티턴 도구 호출(Tool Use) 에이전트를 실시간 구동할 수 있도록 최적화된 온디바이스 SLM (https://blogs.nvidia.com/blog/2026/10/23/nemotron-3-5-bolt-e4b/)
  • r/LocalLLaMA 로컬 에이전트 데일리 드라이버 모델 선정 [커뮤니티 논의/미검증] — 단일 소비자용 GPU(RTX 4090/5090 등) 환경에서 Q4/Q8 양자화 기반 27B~30B 오픈웨이트 모델과 MTP 가속 엔진을 조합해 로컬 자율 에이전트로 운용하는 커뮤니티 티어 리스트 및 벤치마크 공유 논의 (https://www.reddit.com/r/LocalLLaMA/comments/1qwen35_local_tier/)

🛠️ 개발 툴·스킬

  • OpenSpec (@fission-ai/openspec) — 즉흥적 바이브 코딩 대신 구조화된 델타 명세(openspec/specs, openspec/changes)를 기반으로 요구사항 추가·수정·삭제를 점진적으로 병합해 단일 진실 공급원(SSOT)을 유지하는 브라운필드 친화적 Spec-Driven Development(SDD) CLI (https://github.com/Fission-AI/OpenSpec)
  • GitHub Spec Kit (specify CLI) — 프로젝트 헌법(Constitution) 정의부터 명세·계획·태스크 분해·검증까지 엄격한 단계별 승인 게이트를 적용하여 코딩 에이전트의 아키텍처 이탈과 임의 구현을 방지하는 파이프라인 중심 엔터프라이즈 SDD 툴킷 (https://github.com/github/spec-kit)
  • Pydantic AI & LangGraph StateGraphs [커뮤니티 논의/미검증] — 거대 에이전트 프레임워크의 과도한 토큰 소모와 비결정적 루프 문제를 완화하기 위해, 엄격한 정적 타입 검증 및 유한 상태 머신(FSM) 기반의 명시적 제어 흐름으로 회귀하려는 개발자 커뮤니티 아키텍처 논의 (https://news.ycombinator.com/item?id=42000000)

📄 논문·트렌드

  • Heavy-Tailed Memory Traces in Long-Horizon Language Agents — 장기 실행 언어 에이전트의 외부 메모리 참조 빈도가 소수 핵심 상태에 편중되는 멱법칙(Heavy-tailed) 분포를 따름을 규명하고, 순위 기반 코어 상태와 압축 테일 상태를 분리해 최대 24.5% 토큰을 절감하는 CTWM(Core–Tail World Model) 메모리 컨트롤러 제안 (Song & Cai, arXiv:2610.00010, https://arxiv.org/abs/2610.00010)
  • RIDAR: Safeguarding Research Integrity in Autonomous Research Agents — 자율 연구 에이전트의 데이터 위조·변조, 보상 해킹 등 연구 무결성 위반(RIVs) 행위를 정의하고, 사후 궤적 분석과 런타임 피드백 주입을 통해 비윤리적 연구 행동을 36.8% 억제하는 자율 안전 프레임워크 (arXiv:2610.31372, https://arxiv.org/abs/2610.31372)
  • FocusGUI: Focused Omni-Modal GUI Agents — 스트리밍 멀티모달 GUI 에이전트에서 누적된 이력으로 인해 발생하는 순차적 주의산만(Sequential Distraction)을 완화하기 위해, 백본 파인튜닝 없이 단계별 핵심 관측 정보만 잠재 벡터로 동적 압축해 디코더에 주입하는 경량 플러그인 어댑터 (Zhang et al., arXiv:2610.26203, https://arxiv.org/abs/2610.26203)

💡 또리팀 적용 포인트

  • OpenSpec 방식의 명세 델타 워크플로우 적용: 에이전트에게 구현을 바로 지시하기 전 specs/ 및 태스크 목록(tasks.md) 단위로 변경 사양(ADDED/MODIFIED/REMOVED)을 먼저 합의·고정하는 단계를 두어, 세션 간 목표 왜곡(drift)과 환각성 파일 임의 수정을 원천 차단 가능.
  • CTWM(Core-Tail World Model) 기반 2계층 메모리 관리 도입: memory/context.md와 작업일지 등 누적되는 문맥을 즉시 참조가 필요한 핵심 상태(Core)와 장기 보관용 압축 요약 상태(Tail)로 분리 관리함으로써, 컨텍스트 윈도우 한계 도달을 방지하고 프롬프트 토큰 오버헤드를 체계적으로 절감 가능.
