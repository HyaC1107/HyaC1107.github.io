매일 아침 자동 생성되는 AI 소식 다이제스트입니다. 젬또리(Gemini)가 웹을 검색해 정리하고 검수봇이 사실 확인을 거칩니다. [미검증] 표시가 있거나 출처가 홈페이지뿐인 항목은 원문을 확인하세요.

🤖 자동 생성 (Windows 작업 스케줄러 ttori-ai-radar, 매일 08:00 · 젬또리 agy Gemini 3.5 Flash (Medium)). 클또리 검수를 거치지 않은 원문이다. [미검증] 태그가 붙었거나 출처가 도메인 홈페이지뿐인 항목은 채택 전 반드시 원문 확인할 것. flash가 학습데이터를 최신 정보로 착각해 내놓는 경우가 있다.

🤖 모델/LLM 소식

  • Muse Spark 1.2 [미검증] — Meta가 2026년 8월 5일에 발표한 텍스트 및 이미지 통합 생성 기능을 갖춘 코딩 최적화 프론티어 모델 (https://meta.com/ai/muse-spark-1-2 [미검증])
  • LFM2.5-2.6B [미검증] — Liquid AI가 2026년 8월 4일 발표한 온디바이스 에이전트 작업을 타겟으로 2.5GB 미만의 메모리에서 구동 가능한 고효율 경량 모델 (https://liquid.ai/lfm-2-5-release [미검증])

🛠️ 개발 툴·스킬

  • Muse Code [미검증] — Muse Spark 1.2와 함께 출시된 터미널 기반 AI 코딩 에이전트로, 격리된 git worktree 병렬 실행 및 이벤트 로깅을 지원 (https://venturebeat.com/ai/meta-unveils-muse-spark-1-2-and-muse-code [미검증])
  • Hark Handoff [미검증] — 2026년 8월 5일 발표된 브라우저 환경 내 버튼 클릭 및 폼 입력을 수행하는 컴퓨터 사용 에이전트(CUA)로 OM2W 벤치마크 97.7점 기록 (https://businesswire.com/news/hark-handoff-cua-release [미검증])

📄 논문·트렌드

  • HyperAgent (arXiv:2608.02650) — 텍스트 기반 도구 설명을 넘어 툴 스키마 하이퍼그래프(Tool-Schema Hypergraphs)를 도입해 LLM 에이전트의 복잡한 계획 및 도구 호출 성공률을 개선한 연구 (https://arxiv.org/abs/2608.02650)
  • LongHorizon-Harness (arXiv:2608.03061) — 실제 환경에서 초장기(long-horizon) 작업을 영위하는 LLM 에이전트의 효과적인 태스크 상태 관리를 위해 ‘Manage-Execute-Audit (MEA)’ 루프 아키텍처를 제안한 논문 (https://arxiv.org/abs/2608.03061)
  • Real-Time Detection and Repair for LLM Agents (arXiv:2608.02464) — 비용이 많이 드는 LLM Judge 모델 호출을 대체해 에이전트 런타임의 오류를 실시간으로 모니터링하고 자가 수리 및 복구를 수행하는 경량 진단 시스템 연구 (https://arxiv.org/abs/2608.02464)

💡 또리팀 적용 포인트

  • LongHorizon-Harness의 MEA(Manage-Execute-Audit) 프레임워크 도입
    • 이유: CLI 오케스트레이터 프로젝트에서 다단계의 쉘 명령어 실행이나 코드 리팩토링과 같은 장기 태스크를 다룰 때, 실행(Execute) 주체와 실행 결과 및 시스템 사이드 이펙트를 감시/검증(Audit)하는 모니터를 분리된 루프로 설계함으로써 전체 오케스트레이션 과정의 안전성과 예외 처리 능력을 획기적으로 올릴 수 있습니다.
  • Real-Time Detection and Repair의 경량 자가 복구 메커니즘 구축
    • 이유: CLI 에이전트가 패키지 의존성 미비나 빌드 오류 등의 실행 실패 상황을 마주했을 때, 매번 고비용의 LLM API를 호출하여 해결책을 묻기보다, 런타임에 쉘 에러나 환경 상태를 상시 수집하는 가벼운 모니터를 통해 사전에 정의된 자가 복구 로직 또는 롤백 규칙을 신속하게 실행시킬 수 있습니다.
  • Muse Code의 격리된 Git Worktree 병렬 실행 및 이벤트 로깅 설계 차용
    • 이유: 다중 에이전트가 CLI 환경에서 파일 수정이나 테스트 실행을 병렬로 처리할 때, 메인 작업 공간의 소스 코드가 손상되지 않도록 자동으로 격리된 임시 Git Worktree를 스폰하고, 작업 진행 이력을 감사 가능한 이벤트 로그(Event Log) 형태로 기록하도록 설계하여 병렬 생산성과 추적성을 강화할 수 있습니다.
